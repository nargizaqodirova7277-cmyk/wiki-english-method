08-modul

Software Security

Kasbiy ingliz tili, texnik fikrlash va hamkorlikdagi yozuv bir darsda.

Dars pasporti

Yo‘nalish
Software Engineering
Format
O‘rganish · Mashq · Yozish
Daraja
A2–B2

Tahdid, zaiflik va himoya choralarini tushuntirish

Daraja Vaqt Yakuniy natija
A2–B290–110 daqiqaAmaliy security guideline va risk tahlili

O‘quv maqsadlari

  • threat, vulnerability va risk tushunchalarini farqlash;
  • xavfsizlik hodisasini sabab–oqibat bilan tushuntirish;
  • foydalanuvchiga aniq himoya tavsiyasi berish;
  • riskni ehtimol va ta’sir bo‘yicha baholash.

Warm-up

  1. Kuchli parolning o‘zi yetarlimi?
  2. Nega dastur faqat kerakli ma’lumotni yig‘ishi kerak?
  3. Phishing xabarini qanday aniqlaysiz?
  4. Xavfsizlik kimning mas’uliyati?

Technical vocabulary

Termin Sodda ta’rif Misol
threatsomething that may cause harmPhishing is a common threat.
vulnerabilitya weakness that can be exploitedThe old library contained a vulnerability.
risklikelihood and impact of harmThe team evaluated the security risk.
authenticationverifying identityMulti-factor authentication protects accounts.
authorizationdeciding what a user may accessAuthorization blocks access to admin pages.
encryptionprotecting data by encoding itEncryption protects data in transit.
patchan update fixing a problemThe administrator installed the security patch.
phishinga message designed to steal informationThe phishing email copied the university logo.

Reading

A small learning platform stores passwords without strong protection and uses an outdated library. An attacker sends a phishing link to students and gains access to one account. Because authorization rules are weak, the account can view records belonging to other users. The team resets passwords, patches the library, enables multi-factor authentication and corrects access rules. It also informs affected users. The incident shows that security requires several layers, not a single feature.

Comprehension

  1. Which vulnerability exists before the attack?
  2. How does the attacker obtain an account?
  3. Why can one account see other records?
  4. Which four actions does the team take?

Language focus — advice and obligation

  • Users should verify suspicious links.
  • Developers must protect stored passwords.
  • The system must not expose private records.
  • Teams need to install security patches promptly.

Darajali topshiriqlar

Beginner — A2

Talabalar uchun beshta qisqa xavfsizlik qoidasini yozing va ikki termin ishlating.

Intermediate — B1

100–140 so‘zda threat, vulnerability, impact va control ko‘rsatilgan risk tavsifi yozing.

Advanced — B2

180–220 so‘zda voqeaga javob rejasini yozing: detection, containment, recovery, communication va prevention.

Peer-review

  • Threat va vulnerability farqlanganmi?
  • Tavsiya amaliy va aniqmi?
  • Privacy hisobga olinganmi?
  • Riskning ta’siri tushuntirilganmi?

Self-assessment

  • Men threat, vulnerability va riskni farqlay olaman.
  • Men authentication va authorization farqini bilaman.
  • Men himoya choralarini ustuvorlashtirdim.
  • Men foydalanuvchiga tushunarli tavsiya yozdim.
